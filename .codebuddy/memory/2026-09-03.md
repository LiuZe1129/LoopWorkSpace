# 2026-09-03

## P0 执行链路漏洞修复

### 背景
审查 SPEC-GraphFlow 执行链路发现 8 个漏洞，按 P0/P1/P2/P3 分级。本次修复 P0 优先级的 3 个漏洞。

### 修复内容

#### 漏洞3: SpecChange 恢复路径断裂（P0）
- **问题**: `AWAITING_SPEC_CHANGE` 状态后无恢复路径，`EXECUTABLE_RUN_STATUSES` 不含该状态，executor 无法 resume；`supersede-run` 创建全新 Run 不携带旧完成状态。
- **修复**:
  - `scheduler/runs.py:GraphRunStore.rebind_spec()` — 将同一 Run 重新绑定到新版本 SpecSnapshot，校验 spec_id 一致 + version 递增，更新 spec-binding.json + run-state.json + 事件日志。
  - `scheduler/executor.py:DRGExecutor.resume_spec_change()` — rebind + 重置所有 completed/failed/blocked/retry_count → 重新 plan + compile-graph → 继续执行。
  - CLI `resume-run <run_id> <new_snapshot>` 命令。
- **闭环**: `conformance=UNVERIFIED/FAIL → AWAITING_SPEC_CHANGE → 用户发布 v2 → resume-run → rebind → 重新 plan/graph → DONE`

#### 漏洞4: L3 人工审查回路断裂（P0）
- **问题**: `execute_review_node` 确定性 fallback 永远返回 APPROVE，`l3_review` 状态无处理，`awaiting_human_node` 无 executor handler，无恢复机制。
- **修复**:
  - `scheduler/executor.py:run()` 循环增加 `l3_review` 状态分支 → 调用 `await_human_review()` 暂停到 `AWAITING_HUMAN`。
  - `scheduler/executor.py:await_human_review()` — 暂停 Run，写 blocked_nodes，记录 `l3_review_required` 事件。
  - `scheduler/executor.py:resume_human_review(run_id, decision, reason)` — APPROVE 标记节点完成继续执行，REJECT 升级到 ESCALATED。
  - CLI `resume-human-review <run_id> --decision APPROVE|REJECT --reason` 命令。
  - `execute_review_node` 注释更新：确定性 fallback 永远 APPROVE（向后兼容），真实 review agent 通过 `agent_handlers["review-agent"]` 注入可返回 `l3_review` 触发人工审查。
- **闭环**: `delivery_review → l3_review → AWAITING_HUMAN → resume-human-review APPROVE → DONE` 或 `REJECT → ESCALATED`

#### 漏洞2: 幽灵节点（P0）
- **问题**: `graph.py:GRAPHFLOW_NODES` 列出 18 个节点含 4 个分支节点（retry/awaiting_human/awaiting_spec_change/escalated），但 `drg.py:build_execution_graph()` 实际只构建 14 治理节点 + WP 节点，4 个分支节点不在执行图中。
- **修复**: `graph.py` 注释对齐，明确 4 个分支节点为 **executor 状态转换节点**（非图遍历节点）：
  - `retry_node` ← `RetryPolicyRunner.handle_failure()` 副作用
  - `awaiting_spec_change_node` ← `executor.await_spec_change()` 副作用
  - `awaiting_human_node` ← `executor.await_human_review()` 副作用
  - `escalated_node` ← retry 耗尽 / `resume_human_review(REJECT)` 设置终态
  - 恢复路径由 CLI 显式触发（非图边）：`resume-run` / `resume-human-review`

### 文件变更
- `scheduler/runs.py` — +rebind_spec() 方法
- `scheduler/executor.py` — +l3_review 状态分支、+await_human_review/resume_spec_change/resume_human_review 三方法、execute_review_node 注释
- `scheduler/main.py` — +resume-run / +resume-human-review CLI 命令
- `scheduler/graph.py` — 节点分类注释
- `tests/test_scheduler_runtime.py` — +6 个 P0 测试

### 测试
112 tests pass（106 原有 + 6 新增），原有测试无破坏。

## P1/P2 漏洞修复

### P1 漏洞1: 双重状态机裂脑
- **问题**: `state.py:LEGAL_TRANSITIONS`（Mode B TaskCard 状态机）与 `runs.py:RUN_STATUSES`（Mode A RunState 状态机）零交集，`TransitionValidator` 校验 Mode B 对 Mode A 运行无效。
- **修复**:
  - `scheduler/runs.py` 新增 `RUN_LEGAL_TRANSITIONS` 常量 + `is_legal_run_transition()` 函数 — 正式定义 Mode A 状态转换表（BOUND→PLANNING→RUNNING→DONE/AWAITING_HUMAN/AWAITING_SPEC_CHANGE 等），与 executor 实际行为对齐。
  - `scheduler/state.py:LEGAL_TRANSITIONS` 加遗留标记注释 — 明确其为 Mode B TaskCard 状态机，不用于 Mode A GraphFlow RunState。

### P1 漏洞5: 闸门空检查
- **问题**: `gate_auto.py:run_gate_checks()` 对非 `final_gate_node` 且无 `acceptance_ids` 的节点返回空列表，导致 `plan_gate_node`/`architecture_gate_node` 永远 PASS。
- **修复**: `gate_auto.py` 为 `plan_gate_node` 和 `architecture_gate_node` 增加实质性检查：
  - `plan_gate_node`: 检查 `execution-plan.json` 存在且 `work_packages` 数量 > 0
  - `architecture_gate_node`: 检查 `architecture_impact_node.json` artifact 存在且 status=success
  - `final_gate_node`: 保留原始行为（运行所有 acceptance shell 检查）

### P2 漏洞6: done_node 双重定义
- **问题**: `drg.py` 将 `done_node` 纳入执行图，executor 的 `run()` 在所有节点完成后直接设 `state.status = "DONE"`，`done_node` 节点执行（写 generic artifact）与后置 DONE 检查形成冗余。
- **修复**: `executor.py` 新增 `execute_done_node()` 方法：
  - 写入带 `terminal_marker: True` 标记的最小化 artifact（通过 tool contract 校验）
  - 注释明确 DONE 状态转换由 `run()` 后置检查独占，消除双重定义

### P2 漏洞7: 无超时熔断
- **问题**: executor 无 wall-clock timeout、无 per-node timeout、无全局 budget，卡住的 Agent 节点会无限期阻塞 Run。
- **修复**: `DRGExecutor.__init__` 增加 `wall_clock_timeout_seconds` 参数（默认 None=无限制），`run()` 循环顶部检查 elapsed time，超时→设 `state.status = "FAILED"` + `last_error` + `run_timeout` 事件 + 返回 `ExecutorResult(status="FAILED")`。

### 文件变更（P1/P2）
- `scheduler/runs.py` — +RUN_LEGAL_TRANSITIONS +is_legal_run_transition()
- `scheduler/state.py` — LEGAL_TRANSITIONS 遗留标记
- `scheduler/gate_auto.py` — +_check_plan_gate +_check_architecture_gate
- `scheduler/executor.py` — +wall_clock_timeout_seconds +execute_done_node +time import
- `tests/test_scheduler_runtime.py` — +6 个 P1/P2 测试

### 测试
118 tests pass（112 + 6 新增 P1/P2），原有测试无破坏。

## P2 轻量级监督修复（V-8/V-9/V-10/V-11）

### 背景
审查执行链路发现 3 层监督缺失（计数+断路器、异常路径接管、跨调用连续性），导致 4 个新漏洞。采用轻量级方案：读取已有 `events.jsonl` 事件日志进行监督，不修改 `RunState` 结构。

### 修复内容

#### V-8 (P0): 无限制 SpecChange 恢复循环
- **问题**: `resume_spec_change()` 执行全量重置并清零 `retry_count`，无断路器，可无限 rebound。
- **修复**: `_check_run_health()` 读取 `events.jsonl` 中 `spec_rebound` 事件计数，≥3 → FAILED + `run_health_check_failed` 事件。在 `resume_spec_change()` rebind 前调用（阻止第 4 次 rebind），在 `run()` 开头作为二级防线。
- **常量**: `MAX_SPEC_REBOUND_COUNT = 3`

#### V-9 (P1): wall_clock_timeout 非累积
- **问题**: `start_time` 是 `run()` 局部变量，每次调用重置；SpecChange resume → `self.run()` 重置计时器。
- **修复**: `_check_run_health()` 读取首/尾事件时间戳计算累积 wall-clock 时间，>timeout → FAILED。仅当存在 `node_started` 事件时触发（`has_prior_execution` 门控），避免干扰首次调用的 V-7 单次超时。

#### V-10 (P1): execute_node 未捕获异常
- **问题**: `execute_node()` 无 try/except，异常绕过 `handle_failure`，节点卡在 `current_nodes`。
- **修复（主防线）**: `run()` 中 `execute_node` 调用包裹 try/except（4 行），异常 → `handle_failure()` → 重试/升级路径。
- **修复（二级防线）**: `_check_run_health()` 检测 `node_started` 无匹配终端事件（`node_completed`/`node_failed`/`spec_change_requested`/`l3_review_required`）→ 标记为 stuck → FAILED。

#### V-11 (P2): 重试后 run() 不自动继续
- **问题**: CLI `execute` 仅调用一次 `run()`；`handle_failure` 重试设置后 `run()` 返回而非继续。
- **修复**: CLI `execute` 处理器改为 while 循环 — `result.status == "RUNNING"` 时继续调用 `run()`，复用同一 `DRGExecutor` 实例。

### 文件变更
- `scheduler/executor.py` — +`MAX_SPEC_REBOUND_COUNT` +`datetime` import +`_check_run_health()` 方法 +`run()`/`resume_spec_change()` 调用 +try/except 包裹
- `scheduler/main.py` — CLI `execute` 改为 while 循环 + 复用 executor 实例
- `tests/test_scheduler_runtime.py` — +5 个测试（V-8 断路器/V-9 累积超时/V-10 stuck/V-10 异常路由/V-11 续行）

### 测试
123 tests pass（118 + 5 新增），原有测试无破坏。
