### 决策与权衡
- **意图差距审计分层**：`intended-vs-implemented` 是 LLM 方法（读文档意图→读代码证据→逐边界比对→分类），不能在确定性 conformance 节点跑。故分层：确定性层（conformance + 新增 intent_audit.py）只做结构校验（意图文档存在性）；语义级比对固化到 `delivery_review_node` 的 review-agent.md 检查项。
- **GAP_FOUND 不触发 spec_change**：意图-实现差距是实现/文档问题，非 spec 问题。executor 改为：`UNVERIFIED`→spec_change（证据缺失=spec gap）；`GAP_FOUND`→继续到 delivery_review（review-agent 决定 REJECT→RETRY 或 APPROVE）。语义正确且不破坏现有 `test_conformance_gap_raises_spec_change_request`。
- **无文档时优雅 no-op**：确定性测试运行时里 architect 是 stub（不产文档），故 intent_audit 在无 documentation 目录时返回 `NO_INTENT_DOCS` 不产发现，overall 维持 PASS/UNVERIFIED。这保证 55 个测试全绿。
